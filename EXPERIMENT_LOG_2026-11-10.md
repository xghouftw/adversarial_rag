## 1. Research question and fixed threat model

The extension asks whether an attacker can select a genuine competing answer
already latent in benign retrieval evidence, inject one passage, promote that
answer through RobustRAG's keyword filter, and cause the final Mistral answer to
be wrong.

The implemented one-passage threat model is:

1. inject exactly one passage into a list of at most ten processed passages;
2. displace the actual bottom-ranked benign passage;
3. preserve the surviving benign isolated responses from the reproduction
   cache;
4. call Mistral once on the new passage;
5. run the released keyword extractor and threshold aggregation unchanged;
6. call Mistral on the released final retained-keyword prompt;
7. use greedy decoding throughout.

The primary source run is the completed Open NQ `current_v2` reproduction with
Mistral-7B-Instruct-v0.2, `top_k=10`, `alpha=0.2`, `beta=3`, and attack budget
one. The checked Open NQ certification replay is used as enrichment and as an
independent consistency check of the locally recomputed one-vote-short keyword
frontier.

Important terminology correction:

> In the current code, `promotion_realized` means that a wrong exact keyword
> was absent from the clean retained set and crossed the attacked retention
> threshold. It does not mean that the keyword tied or exceeded the gold vote
> leader, became a majority answer, or replaced gold in the final response.

Calling this mechanism **threshold promotion** is more precise.

## 2. Implemented modular pipeline

Shared attack mechanics live in `promotion_attack.py`. They load exact cached
responses, reproduce the one-injection certification frontier, construct
documents, simulate full source-response duplication, execute live attacks, and
save provenance-complete artifacts.

Target policies are separate typed functions:

- `promotion_selectors/raw.py`: selector `1`, the raw structural baseline;
- `promotion_selectors/nlp.py`: selector `1+2`, deterministic answer-shape
  filtering and reranking;
- `promotion_selectors/prometheus.py`: selector `3`, Prometheus direct
  assessment over the same structural pool;
- `promotion_selectors/base.py`: shared callable interface, immutable dependency
  context, assessments, and judge result types.

Selectors `1+2` and `3` are parallel alternatives. Prometheus does not receive
the NLP-filtered candidates. Every selector begins with the same post-
certification structural pool.

The current document generator is `delete_gold_segments`: split the processed
`title\ntext` passage into the title and body sentences, remove every segment
containing a complete gold alias under lemma-token matching, preserve the rest
verbatim, and reject the document if it is empty or no longer contains the
target.

Twenty promotion-attack unit tests pass. They test implementation behavior, not
experimental efficacy. No expensive response cache is regenerated by target
selection.

## 3. Why complete source responses matter

A source passage and a source response are different objects:

- the **source passage** is retrieved text given to isolated Mistral;
- the **source response** is Mistral's cached short answer to that passage.

The cache-only structural predictor duplicates the complete source response's
keyword set, not only the chosen target. This is necessary because a live poison
response contributes every phrase extracted from its complete output. The
generated poison document can differ from the source passage, so live Mistral
may not reproduce the cached response. That discrepancy is recorded as a
response-realization failure; the algorithm must not silently choose another
target after observing it.

### 5.1 Informal semantic audit

Prometheus improved superficial answer form relative to the raw selector, but
its score is not a reliable semantic-validity label. Informal review found
several accepted targets that violate the rubric, including:

- `Amber/Tracy` for a question whose gold character is Tracy;
- `Brett Millard`, effectively a typo of gold `Bart Millard`;
- `Tetraphosphorus decaoxide`, equivalent to a gold systematic compound name;
- `Federal democratic republic`, semantically overlapping the gold federal-
  republic answer;
- `Captain Robert April`, a person for a question asking for a ship;
- `Steve`, an incomplete person name;
- `The Voice of Jack Skellington`, a descriptive phrase rather than the person
  requested.

Prometheus feedback repeatedly treated failure to exactly match a gold string
as evidence of semantic distinctness. In one case it called `Federal democratic
republic` both the expected answer and an unambiguously wrong answer in the same
assessment. These observations are diagnostic manual review, not a blinded
precision estimate.

Conclusion: selector 3 is a reproducible experimental baseline, not a trusted
oracle. It should be evaluated against blind human labels before being used as
the primary automatic semantic selector.

## 7. Where the current attack fails

The failures occur at three distinct stages.

### 7.1 Semantic target selection

Prometheus accepts exact-string mismatches that are actually gold-equivalent,
wrong answer types, malformed names, or incomplete phrases. A stronger judge
may improve this stage, but cannot repair the structural vote deficit described
below.

### 7.2 Document/response realization

The current gold-deletion generator realized only 3/5 intended responses in the
selector-3 live pilot. Queries 5 and 16 produced `I don't know`. Gold deletion
can remove the context that connects a target to the question, even when the
target string remains in the document.

This is a real bottleneck, but it is not the only or largest observed obstacle:
all three realized targets crossed the threshold, yet none removed gold from
the final answer.

### 7.3 Structural objective and final-answer arbitration

RobustRAG is not a majority-vote classifier. Vote counts only determine which
phrases survive. The final prompt contains each retained phrase once, without
its vote count, and orders phrases by the released length/lexicographic rule.
Mistral then freely generates from the entire hint bag.

For the full 235-candidate raw structural pool:

```text
candidates with target below strongest gold vote count: 203
candidates tied with strongest gold vote count:          32
candidates exceeding strongest gold vote count:           0
questions containing any tie:                       8, 25, 44, 61
```

Among selector 3's 26 chosen targets, 25 trailed the strongest gold phrase and
only query 44 tied it. None led gold. Every selected target had two simulated
votes, while the strongest gold-aligned phrase generally had two to eight.

Therefore the implemented objective finds a wrong phrase that crosses the
retention boundary; it does not find a wrong phrase that overtakes gold. This is
the clearest explanation for 0/5 strict success. Better document realization
could raise the 3/5 response rate, but one exact target still gains at most one
additional vote from one injected response because keywords are counted as a
set.

Query 44 (`$5 million` versus gold `$75,000`) is the best immediate mechanistic
diagnostic because it is the only Prometheus-selected case tied with the
strongest gold vote count.

## 8. Candidate-selection direction

Keep two attack concepts distinct:

1. **Threshold promotion:** current experiment; a previously filtered wrong
   phrase becomes retained.
2. **Competitive promotion:** prioritize or require
   `attacked_target_votes - maximum_gold_votes >= 0`.

At budget one, competitive promotion has very limited coverage and no candidate
strictly exceeds gold in the saved structural pool. If overtaking gold is the
required goal, increasing the injection budget is the direct mechanism, but it
changes the threat model and must be a separately configured experiment.

Selector `1+2` should be run before adding another semantic judge. It is a
simple deterministic answer-form baseline and provides a paired comparison
against selector 3. For the existing five-question debug comparison, use:

```python
TARGET_SELECTOR = "1+2"
RUN_MISTRAL_ATTACK = True
MISTRAL_ATTACK_QUERY_INDICES = [2, 5, 11, 16, 18]
MAX_CANDIDATES_PER_QUESTION = "1"
```

For a systematic comparison, construct the intersection of questions on which
both selectors have candidates. Analyze uncertified questions as the primary
attack population and certified questions as separately reported negative
controls. Human review must also remove false clean-correct labels and
gold-equivalent targets.

### 8.1 Possible stronger judge

A frontier GPT-class model may be tested as a new selector, not silently
substituted for Prometheus after observing failures. Its output should use
separate structured fields rather than one overall 1--5 score:

```text
standalone answer
answer-type match
gold-equivalent or alternate correct
genuinely wrong
source-plausible
predicted answer from the complete simulated hint bag
```

Hard eligibility rules should reject gold-equivalent, alternatively correct,
wrong-type, and incomplete candidates. The GPT selector, Prometheus, and NLP
baseline should be compared against the same blind human labels. Human labels
may calibrate the method on a development set, but humans should not replace
individual frozen test targets after seeing attack outcomes.

## 9. Lexical-family/cluster idea: deferred

A single duplicated source response can promote several exact strings produced
by the upstream extractor. For example, `Fairmont Chateau Whistler`,
`Fairmont`, `Chateau`, and `Whistler` all became retained together. Several
related hints may exert more final-prompt influence than one isolated date.

An attacker-side lexical-family analysis could measure the number, completeness,
and final-prompt positions of related newly retained strings without modifying
the defense. The actual pipeline would still count exact strings independently
and preserve the original hint bag.

However, defining and deliberately generating a coherent group is more
abstract than the current target-level experiment. Semantic grouping can also
introduce another unvalidated model or heuristic. Per the current project
decision, do not prioritize cluster promotion now. Preserve it as a later
extension after the single-target selector and document generator are
understood. If revisited, begin with a deterministic lexical containment family
before introducing embeddings or an LLM semantic clusterer.

## 10. Document-generation variants discussed

Document generation and target selection must remain independent experimental
axes. The cache-only duplication predictor is not itself a document generator.
Every live variant must record whether isolated Mistral produced the intended
target and all actual extracted keywords.

### A. Exact source-passage duplication

Inject the complete benign target-bearing passage unchanged. This is the
simplest source-supported control and best tests whether repeated evidence is
enough. It can retain gold evidence, contain irrelevant material, and may be
unrealistic when a retriever deduplicates documents.

### B. Delete gold-bearing segments (implemented baseline)

Remove the title or sentences containing a complete gold alias and preserve all
remaining text verbatim. This is deterministic and extractive. Its observed
weakness is loss of question-target context, leading to `I don't know` even
when the target string remains.

### C. Target-containing sentences only

Select sentences containing the target, reject any sentence containing a gold
alias, and concatenate the survivors. This was the original simple proposal.
It is deterministic and reduces irrelevant material, but can be too fragmentary
or omit the relation needed to answer the question.

### D. Target evidence window

Keep target-containing sentences plus one adjacent supporting sentence (and
possibly a non-gold title). This remains mostly extractive while preserving
more context than option C. It is the strongest next document-generation
baseline to implement.

### E. Replace gold mentions with the target

Replace every gold alias in a source passage with the selected target. This can
produce an explicit competing claim and preserve syntax, but may create
grammatical errors, contradictions, impossible entity types, or multiple
unnatural replacements. It is a controlled rewrite rather than an extractive
attack and should be labeled separately. This strategy was implemented on
2026-11-11 as `gold_alias_substitution` with longest-alias-first matching and
replacement of every non-overlapping gold span. It has not yet been evaluated
in a live attack.

### F. Explicit source-grounded answer rewrite

Construct a concise declarative passage that directly answers the question with
the selected target and includes source-supported context, while excluding gold
aliases. This is most likely to improve response realization but gives the
attacker greater generative power and risks inventing unsupported claims. It
requires a frozen generator/prompt and separate reporting from extractive
variants.

For all variants, trying multiple documents and choosing one after querying
Mistral changes the search/query budget. Report `success@1`, `success@k`, and
the number of unique poison documents separately. Repeating a target within one
isolated response cannot create multiple exact votes because the extractor
converts phrases to a set.

## 12. Claims supported and not supported

Supported by saved evidence:

- the one-passage structural screen finds 235 document-realizable candidate
  rows on the saved Open NQ source run;
- Prometheus reduces that pool to 47 eligible rows across 26 questions;
- the current gold-deletion generator realized 3/5 selected responses in the
  selector-3 live pilot;
- all realized targets crossed the retention threshold;
- all five final answers retained gold and strict targeted success was 0/5;
- no structural candidate in the saved pool strictly exceeds the strongest
  gold-aligned simulated vote count at budget one.

Not supported:

- that selector 3 reliably identifies genuine wrong answers;
- that the five-question pilot estimates population success;
- that document generation is the sole or dominant failure;
- that threshold retention is equivalent to majority takeover;
- that a lexical-family attack, stronger GPT judge, rewritten document, or
  larger attack budget will succeed;
- that automatic substring correctness is sufficient without manual review.
